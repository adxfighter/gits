# Зависание взаиморасчётов операторов связи

Операторы связи ежедневно рассчитываются друг с другом за роуминг и межсетевой трафик. Каждый расчёт — вызов `SettlementService.settle(payer, payee, amount)`: сумма списывается со счёта оператора-плательщика, зачисляется получателю за вычетом комиссии, а комиссия поступает на счёт клирингового центра. Расчёты между разными парами операторов выполняются параллельно. Правило системы: баланс счёта меняется только под монитором объекта `OperatorAccount`.

## Что наблюдается
В дни закрытия периода, когда операторы массово рассчитываются друг с другом в обе стороны, сервис периодически зависает. Дамп потоков показывает, что потоки ждут мониторы счетов операторов. Предыдущая попытка исправления — поменять местами строки внутри `settle` — не помогла: часть блокировок захватывается во вспомогательном методе.

## Что нужно сделать
Устраните зависание так, чтобы каждый расчёт оставался атомарным, комиссия всегда попадала на счёт клиринга, а сумма денег в системе не менялась.

## Ограничения
- Публичные методы и их сигнатуры менять нельзя.
- Класс `OperatorAccount` доступен только для чтения; правило блокировок сохраняется.
- Размер комиссии и проверки аргументов должны остаться прежними.

## Как будет проверено
Видимые тесты проверяют расчёт в одном потоке. Скрытые тесты выполняют встречные расчёты из нескольких потоков с ограничением времени и проверяют сохранение денег.
