# ADR 0002. Схема базы данных v1.0

**Статус:** принято. **Дата:** 2026-09-27. **Миграция:** `backend/gits-api/src/main/resources/db/migration/V1__init_schema.sql`.

## Решения
| Вопрос | Решение | Почему |
|---|---|---|
| Владелец схемы | Только Flyway в gits-api; Hibernate — `ddl-auto: validate` в api и runner | Схема версионируется миграциями; расхождение сущностей и схемы обнаруживается при старте и в тестах |
| Первичные ключи | UUID, генерирует Hibernate | Идентификаторы не угадываются перебором и не раскрывают объём данных |
| Время | `timestamptz` ↔ `Instant` | Единая шкала UTC |
| Перечисления | `varchar` + `CHECK` в БД, `@Enumerated(STRING)` в коде | Читаемо в SQL, защита от мусорных значений на уровне БД |
| JSON-поля | `jsonb`, в сущностях — строка с `@JdbcTypeCode(SqlTypes.JSON)` | Гибкие структуры (телеметрия, параметры сложности, индикаторы) без жёсткой схемы; разбор — в сервисах |
| Email | Уникальный индекс по `lower(email)` | Регистронезависимый вход |
| Токен приглашения | Хранится только SHA-256 (`token_hash`) | Утечка базы не даёт рабочих ссылок |
| Очередь запусков | Таблица `run_job`, частичный индекс по `created_at WHERE status='QUEUED'`, выборка `FOR UPDATE SKIP LOCKED` | Надёжная очередь без Redis; параллельные исполнители не берут одно задание (проверено тестом) |
| Идемпотентность телеметрии | `UNIQUE (session_task_id, seq)` | Повторная отправка пакета не создаёт дубликатов |
| Удаление | Банк задач — `RESTRICT` (варианты отключаются через `DISABLED`, а не удаляются); данные сессии — `CASCADE` от сессии и задачи сессии | Старые сессии всегда ссылаются на исходные задачи; удаление сессии чистит всё зависимое |
| Работодатель и компания | `CHECK`: у роли EMPLOYER обязательно `company_id`; у ADMIN может не быть | Изоляция данных по компаниям начинается с модели |

## Таблицы
- **Учётные записи:** `company`, `app_user`.
- **Банк задач:** `task_template`, `task_variant`, `task_file` (виды файлов STARTER, SOLUTION, VISIBLE_TEST, HIDDEN_TEST, READONLY; SOLUTION и HIDDEN_TEST никогда не отдаются кандидату — см. `FileKind#isCandidateVisible`).
- **Приглашения:** `invite`, `consent`.
- **Сессии:** `assessment_session`, `session_task`.
- **Исполнение кода:** `run_job`, `run_result`.
- **Телеметрия и результаты:** `telemetry_batch`, `session_indicators`, `session_score`.
- **Аудит:** `audit_log`.
