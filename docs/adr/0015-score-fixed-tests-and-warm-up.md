# ADR 0015. Балл по исправленным тестам, разминка в балле, подсветка причин

**Статус:** принято. **Дата:** 2026-09-28. **Этап:** доработка P12 по ручному тестированию владельца (после P16). Заменяет строки «Разминка» и «Балл» [ADR 0008](0008-indicators-and-score.md).

## Контекст
Владелец прошёл сессию, ничего не решив, и получил 25,71 балла: в задачах «найди и исправь ошибку» часть скрытых тестов проверяет уже работающее поведение и проходит на исходном коде. Решения владельца: считать только тесты, которые исходный код не проходит; разминку учитывать с весом 0,5 по тестам части 2 и честно сказать об этом кандидату; подсвечивать строки индикаторов, из-за которых есть замечания; отдельного правила для «перепечатывал везде» не вводить.

## Решения
| Вопрос | Решение | Обоснование |
|---|---|---|
| Какие тесты считаются | Исправляющие — скрытые проверки (каждая строка параметризованного теста — отдельная), которые заготовка проваливает хотя бы в одном прогоне валидатора. Проверки «ничего не сломано» — проходящие во всех прогонах, выдавших отчёт. Прогон без отчёта (зависание, сбой) о проверках ничего не говорит и не учитывается; если отчёта не было ни разу (заготовка всегда зависает, как при взаимной блокировке), исправляющими считаются все скрытые тесты | Нетронутый код — 0; тест, который заготовка проходит лишь иногда (гонка потоков), — цель исправления |
| Сломанная проверка «ничего не сломано» | Задание — 0 | Решение, которое чинит одно и ломает другое, не засчитывается |
| Неизменённый код | 0, даже если нестабильный тест случайно прошёл | «Кандидат ничего не сделал — 0» |
| Как узнать вид теста | `TestKey` — 16 знаков SHA-256 от «класс#метод»; runner хранит его у каждого скрытого теста (`test_cases[].key`), валидатор версии 2 — список ключей проверок «ничего не сломано» (`runs.starter_passing_hidden`); весь банк перепроверен | Имена скрытых тестов не хранятся в результатах (ADR 0004) — ключ их не раскрывает |
| Требование к варианту | Проверка валидатора `starter_fails` дополнительно требует хотя бы одной исправляющей проверки (если заготовка вообще выдаёт отчёт) | Иначе задание невозможно решить на балл |
| Старые данные | Результат без ключей или вариант без списка — все скрытые тесты, как раньше; неизменённый код — 0 и для старых сессий после пересчёта. Загрузчик банка обновляет в базе отчёт валидации, даже если содержимое варианта не менялось (новый валидатор пишет больше) | Пересчёт старых сессий не ломается; базы, загруженные раньше, получают списки проверок |
| Отчёт работодателя | Что учтено (`counted`) берётся из сохранённого балла сессии, чтобы карточки и итог совпадали; до расчёта — по последнему SUBMIT | Иначе после смены правил карточки и балл расходились бы до пересчёта |
| Разминка | Вес 0,5 (`gits.scoring.calibration-weight`), доля тестов части 2; перепечатка не входит. Тексты кандидату: правила, условие разминки, сообщение после отправки | Честность перед кандидатом (условие разминки и сообщение после отправки говорили «не влияет») |
| Подсветка причин | Сработавшее правило хранит уровень и индикаторы отчёта (`trustRules`); строки этих индикаторов подсвечены цветом уровня с отметкой ▲ (и текстом для экранного диктора), у причин — уровень словами | Работодатель сразу видит, откуда замечание |
| «Перепечатывал везде» | Без нового правила: каждая такая задача получает YELLOW «набрано сверху вниз», с быстрой печатью — ещё «скорость выше разминки», с уходами и паузами — «всплеск после паузы» и RED | Решение владельца; надёжно отличить перепечатку от уверенного набора в v1.0 нельзя |

## Последствия
- Демо-сессии записаны до доработки (результаты без ключей): их задачи считаются по всем скрытым тестам, а разминки без решённой части 2 теперь снижают балл.
- Условие разминки изменилось — у трёх вариантов CAL новый `content_hash`.
- Ключи теста — формат имени JUnit в отчёте песочницы: после обновления JUnit в образе песочницы банк нужно перепроверить, иначе ключи перестанут совпадать и засчитываться будут все скрытые тесты.
- Кандидат после отправки по-прежнему видит «пройдено X из Y» по всем скрытым тестам: ненулевое число там может означать 0 в балле.
- Балл старых сессий меняется только после пересчёта (`POST /api/admin/sessions/{id}/scoring`).
