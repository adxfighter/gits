# Телеметрия ввода кандидата

Страница задачи собирает события ввода в редакторе и отправляет их пакетами. По ним строятся индикаторы (P12) и воспроизведение сессии (P14). Модель события — `TelemetryEvent`, приём — `TelemetryService` (gits-api), хранение — таблица `telemetry_batch` (`events` и `flags` — JSONB).

## Отправка
| Способ | Запрос | Защита от CSRF |
|---|---|---|
| Обычный, раз в 2 секунды | `POST /api/candidate/tasks/{id}/telemetry`, `Content-Type: application/json` | заголовок `X-XSRF-TOKEN`, как у остальных запросов |
| `navigator.sendBeacon` при скрытии или закрытии страницы | тот же путь, `Content-Type: text/plain` с JSON в теле | одноразовый токен `beaconToken` в теле пакета |

Одноразовый токен выдаётся в ответе `GET /api/candidate/tasks/{id}` (поле `beaconToken`, пока задание выполняется). Каждое открытие задания выдаёт новый токен, предыдущий перестаёт действовать. Токен расходуется, когда sendBeacon успешно сохранил новый пакет; отклонённый пакет и повтор уже принятого `seq` токен не расходуют. Токен отзывается и при отправке задания. Новый токен вернёт следующий обычный пакет в поле `beaconToken` ответа; в остальных ответах это поле равно `null`. Хранится только SHA-256 токена (`session_task.beacon_token_hash`).

Пакет:
```json
{"seq": 0, "clientTsStart": 0.0, "clientTsEnd": 1998.4, "events": [ ... ], "beaconToken": "только для sendBeacon"}
```
- `seq` — номер пакета задания, начиная с 0.
- `clientTsStart` и `clientTsEnd` — границы интервала пакета в той же шкале, что `t`.

Ответ `200`:
```json
{"seq": 0, "duplicate": false, "flags": {}, "beaconToken": null}
```

## Правила приёма
| Правило | Ответ |
|---|---|
| Повтор пакета с тем же `seq` (в том числе после закрытия задания) | `200`, `duplicate: true`, повторно не сохраняется; `flags` в ответе пустые |
| Больше 2 000 событий или больше 256 КБ тела | `413` |
| Некорректный JSON, нет `seq`/`clientTsStart`/`clientTsEnd`/`events`, событие не по схеме, число в виде строки или дробный `seq` | `400` с номером события; пакет не сохраняется |
| Чужое или несуществующее задание | `403` |
| sendBeacon без действующего `beaconToken` (в том числе после отправки задания) | `403` |
| Задание не открыто, отправлено, время сессии истекло или сессия завершена | `409` |

Лимиты задаются в `gits.telemetry.*` (`application.yml`). Пакеты одного кандидата принимаются последовательно, вместе с остальными его запросами (блокировка строки приглашения). Перед «Отправить» страница должна отправить накопленные события: после SUBMIT новые пакеты не принимаются.

### Монотонность времени
Нарушения не отклоняют пакет. Они записываются в `flags` пакета и возвращаются в ответе:
- `tNotMonotonic` — внутри пакета `t` убывает;
- `outsideBatchRange` — событие вне `[clientTsStart, clientTsEnd]` или `clientTsEnd < clientTsStart`;
- `overlapsPreviousBatch` — `clientTsStart` меньше `clientTsEnd` пакета с ближайшим меньшим `seq`;
- `overlapsNextBatch` — `clientTsEnd` больше `clientTsStart` пакета с ближайшим большим `seq` (пакеты могут прийти не по порядку).

## Событие
Общие поля:
- `t` — миллисекунды от начала задачи (`performance.now()` относительно открытия задания), дробное, не меньше 0;
- `type` — тип события.

Сервер сохраняет только поля, относящиеся к типу события. Всё остальное, что прислал клиент, отбрасывается. События `kd` и `ku` не несут символа клавиши: даже если клиент его прислал, он не сохраняется. Набранный и вставленный текст сохраняется в событиях `edit` — это нужно для воспроизведения сессии, и об этом честно сообщают кандидату (P10). `file` — путь файла задания, не длиннее 300 символов.

| type | Поля | Смысл |
|---|---|---|
| `kd`, `ku` | `keyClass`, `repeat` (обязателен для `kd`) | нажатие и отпускание клавиши. Передаётся только класс клавиши, символ не передаётся |
| `edit` | `file`, `rangeOffset`, `rangeLength`, `textLength`, `text`, `isUndo`, `isRedo`, `source` | изменение текста в редакторе: заменён диапазон `[rangeOffset, rangeOffset + rangeLength)` на `text`, `textLength` = длина `text` (UTF-16, как `String.length` в JS) |
| `cursor` | `file`, `offset` | позиция курсора (смещение в файле) |
| `select` | `file`, `offset`, `length` | выделение |
| `paste`, `copy` | `file`, `length` | вставка и копирование, только длина |
| `completion` | `accepted`, `insertedLength` | подсказка автодополнения: принята или нет, длина вставки |
| `visibility` | `state`: `visible` \| `hidden` | видимость вкладки |
| `focus`, `blur` | — | фокус окна |
| `run`, `submit` | — | нажатие «Запустить» и «Отправить» |
| `resize` | `width`, `height` | размер окна редактора, больше 0 |

Значения:
- `keyClass`: `letter`, `digit`, `space`, `enter`, `backspace`, `delete`, `tab`, `arrow`, `punct`, `bracket`, `modifier`, `other`;
- `source` (для `edit`): `typing`, `paste`, `completion`, `other`.

Для `edit` флаги `isUndo` и `isRedo` необязательны, по умолчанию `false`. Для `kd` и `ku` значение `repeat` по умолчанию `false`.

Пример пакета:
```json
{"seq": 3, "clientTsStart": 6000.0, "clientTsEnd": 7999.2, "events": [
  {"t": 6012.4, "type": "kd", "keyClass": "letter", "repeat": false},
  {"t": 6013.1, "type": "edit", "file": "src/main/java/Solution.java", "rangeOffset": 120, "rangeLength": 0,
   "textLength": 1, "text": "x", "source": "typing"},
  {"t": 6090.0, "type": "ku", "keyClass": "letter"},
  {"t": 7400.8, "type": "visibility", "state": "hidden"}
]}
```

Сбор в браузере (источники событий, прореживание, буфер) описывает P11.
