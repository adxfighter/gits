# ADR 0013. Раздел администратора и выгрузка для исследования

**Статус:** принято. **Дата:** 2026-09-28. **Этап:** P15.

## Контекст
Администратору платформы нужны банк задач (включая решения и скрытые тесты), сессии всех компаний с пересчётом балла, а научному руководителю — выгрузка данных для исследования без персональных данных кандидатов (P15).

## Решения
| Вопрос | Решение | Обоснование |
|---|---|---|
| Доступ | `/api/admin/**` — роль ADMIN (SecurityConfig); работодателю 403, без входа 401. Во фронтенде — `adminGuard`, вход ведёт администратора в `/admin/tasks`, работодателя — в `/employer`; страницы чужой роли переводят в свой раздел; возврат после входа — только в свой раздел | Решения и скрытые тесты не должен увидеть никто, кроме администратора |
| Где видны секретные файлы | Только `GET /api/admin/tasks/variants/{id}`; в интерфейсе они помечены замком и пояснением | Остальные ответы API по-прежнему их не содержат (проверки `assertNoSecrets`) |
| Сессии | Все компании, новые первыми, с меткой кандидата: администратор — оператор платформы. Пересчёт — существующий `POST /admin/sessions/{id}/scoring` | Для экспорта метки не нужны, для поддержки — нужны |
| Формат выгрузки | ZIP: `README.md` (описание полей, ресурс `export/README.md`), `sessions.jsonl`, `tasks.jsonl`, `runs.jsonl`, `telemetry.jsonl` (пакет на строку, как прислал браузер), `indicators.jsonl`, `manifest.json` (формат `gits-research-export/1`, период, число строк) | JSONL читается построчно любыми средствами (Python, R, jq), большие файлы не надо загружать целиком |
| Псевдонимизация | Сессии, задания и компании получают **случайные идентификаторы этого архива** (`s-`, `t-`, `c-` и 16 шестнадцатеричных знаков из `SecureRandom`); ссылки на задания внутри `scorePerTask` заменяются теми же псевдонимами | Идентификатор, выведенный из данных (хеш id), позволил бы связать архив с базой или две выгрузки между собой |
| Что не выгружается | Метка кандидата, email, название компании, IP и его хеш, user agent, токены. Выгружаются: время (UTC), уровень, код и события ввода, результаты тестов, индикаторы, версия согласия | Код и ввод — предмет исследования, кандидат на это согласился; идентифицирующие данные исследованию не нужны |
| Период | `from`/`to` — дни начала сессий по UTC, включительно, оба необязательны | Просто и однозначно для научного руководителя |
| Потоковая отдача | `StreamingResponseBody`, архив пишется прямо в ответ внутри одной read-only транзакции; телеметрия читается по одному заданию | Выгрузка за длинный период не должна помещаться в память |
| Аудит | Каждая выгрузка — строка `audit_log` (`RESEARCH_EXPORT`, кто и за какой период) до начала отдачи | Выдача данных для исследования должна быть прослеживаема |
| Скачивание в интерфейсе | Обычная ссылка `download` на `/api/admin/export?...`: браузер скачивает файл с cookie сессии | Без чтения архива в память страницы |

## Последствия
- Время событий и дни сессий в архиве остаются точными: связать архив с человеком может тот, кто знает, когда он проходил оценку. Для v1.0 это приемлемо (выгрузка — для научного руководителя по договору); в версии НИОКР — огрубление времени или k-анонимизация.
- Код и текст, набранные кандидатом, выгружаются как есть: если кандидат напечатал в коде своё имя, оно попадёт в архив.
- Тест `AdminApiTest` проверяет, что в архиве нет метки кандидата, email работодателя и администратора, названия компании, user agent, хеша IP, идентификаторов сессии, приглашения и заданий, и что две выгрузки дают разные псевдонимы.
