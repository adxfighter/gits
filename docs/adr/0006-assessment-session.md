# ADR 0006. Сессия оценки: подбор задач и параллельные запросы кандидата

**Статус:** принято. **Дата:** 2026-09-28. **Этап:** P07.

## Контекст
Кандидат работает в одной сессии оценки (90 минут, разминка + 3 задачи) из браузера. Двойной клик, вторая вкладка или перезагрузка страницы шлют одновременные запросы. Параллельно планировщик закрывает сессии, у которых вышло время. Без согласования запросов появлялись вторая сессия, второй активный запуск, двойной SUBMIT, а поздний автосейв перезаписывал статус, выставленный планировщиком.

## Решения
| Вопрос | Решение | Обоснование |
|---|---|---|
| Состав сессии | JUNIOR — J, J, M; MIDDLE — J, M, S или M×3; SENIOR — M, S, S; шаблоны задач различаются; калибровочный блок — независимо от уровня | Уровень приглашения задаёт сложность, разные шаблоны — разные компетенции |
| Разнообразие | Варианты трёх последних сессий компании не выдаются, пока банк это позволяет; выбор детерминирован по `random_seed` сессии | Кандидаты одной компании не получают одинаковые задачи; сессию можно воспроизвести |
| Параллельные запросы | Каждое изменение сессии кандидата (старт, открытие задания, автосейв, RUN, SUBMIT, завершение, приём телеметрии, расчёт балла) сначала берёт `SELECT … FOR UPDATE` строки приглашения | Одна точка сериализации на кандидата; без версионных колонок и повторов транзакций |
| Истечение времени | Планировщик раз в 30 с выбирает просроченные сессии SQL-запросом и закрывает каждую в своей транзакции | Одна сбойная сессия не мешает остальным |
| Лимиты | Автосейв не чаще раза в 5 с, код до 256 КБ, один активный запуск на кандидата, 60 RUN на задачу; время — по часам сервера | Защита песочницы и базы; клиенту нельзя верить в вопросе времени |
| Что видит кандидат | Только STARTER, READONLY, VISIBLE_TEST; у SUBMIT — только число пройденных скрытых тестов | Скрытые тесты и эталон не должны утекать |

## Последствия
- После завершения приглашение получает статус COMPLETED, и cookie кандидата перестаёт действовать (401): кандидат не видит свой результат. Разрешить ему доступ только на чтение к итогам — решение владельца продукта, в v1.0 не принято.
- Блокировка строки приглашения — простая, но пессимистичная: запросы одного кандидата выполняются строго по очереди. Для одного кандидата это незаметно.
