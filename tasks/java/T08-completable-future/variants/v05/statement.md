# Сбор результатов анализов из четырёх лабораторий

Анализы по направлению пациента выполняют несколько лабораторий-партнёров. `LabResultsCollector.collect(orderId)` асинхронно запрашивает результат у каждой лаборатории (`Lab.result`) и возвращает `CompletableFuture<LabReport>`.

В отчёте:
- `results` — результаты ответивших лабораторий по имени лаборатории;
- `failures` — для каждой лаборатории без результата причина: `"timeout"`, если лаборатория не ответила за `labTimeout`, иначе сообщение исключения лаборатории (или простое имя класса исключения, если сообщения нет);
- `isComplete()` — истинно, только если ответили все лаборатории.

Врач видит неполный отчёт с пометкой, какие анализы не пришли и почему.

## Что наблюдается
- Врачи получают отчёты с пометкой «полный», хотя части анализов в них нет.
- Если одна из лабораторий не отвечает, отчёт не формируется вообще, а пул потоков сервиса постепенно заполняется «зависшими» задачами.
- Клиентская библиотека одной из лабораторий иногда бросает исключение прямо из `result`, и тогда отчёт падает целиком.

## Что нужно сделать
Исправьте `LabResultsCollector.collect` в соответствии с описанием отчёта. Ожидание ответов не должно занимать потоки пула `executor`.

## Ограничения
- `Lab`, `LabResult`, `LabReport` доступны только для чтения; конструктор и сигнатура `collect` не меняются.
- Результат лаборатории, пришедший после таймаута, в отчёт не попадает.

## Как будет проверено
Тесты используют лаборатории-заглушки, которые тест завершает вручную, пул из одного потока и таймаут 100 мс. Видимые тесты проверяют случай, когда ответили все лаборатории. Скрытые тесты проверяют ошибки, таймауты, исключения из `result` и занятость пула.
