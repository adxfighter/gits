# GITS v1.0 — локальная демо-версия

Платформа оценки практических навыков Java-разработчиков: кандидат решает задачи в веб-редакторе кода, код исполняется в изолированном Docker-контейнере, работодатель получает отчёт и воспроизведение сессии.

Версия v1.0 работает полностью локально в Docker Compose — без облака и внешних API.

## Требования
- Docker Desktop (Windows 10/11: бэкенд WSL2) или Docker Engine с Compose v2 (Linux), Git.
- 16 ГБ RAM рекомендуется (Docker — от 6 ГБ), 20 ГБ свободного диска. Для 10 одновременных кандидатов — 8 потоков CPU и `RUNNER_CONCURRENCY=4` ([docs/performance.md](docs/performance.md)).
- Для разработки: JDK 21, Maven 3.9+, Node.js 24 LTS.

## Быстрый старт за 5 шагов
1. Установите и запустите Docker Desktop (Windows) или Docker Engine с Compose v2 (Linux).
2. Клонируйте репозиторий: `git clone https://github.com/adxfighter/gits.git`. На Windows — в папку с коротким путём (например, `C:\gits` или `Документы\gits`): самые длинные пути файлов банка задач — 140 символов, и при пути к папке длиннее ~115 символов Git не сможет создать файлы (Filename too long). Если короткий путь невозможен — `git config --global core.longpaths true` до клонирования.
3. Скопируйте `.env.example` в `.env` и задайте свои значения: пароли `POSTGRES_PASSWORD`, `DEMO_EMPLOYER_PASSWORD`, `DEMO_ADMIN_PASSWORD`; у работодателя и администратора — **разные** email; `GITS_CANDIDATE_SECRET` — длинная случайная строка (пустая — кандидатов разлогинит при перезапуске api). Если `.env` нет, скрипт запуска создаст его из примера с демо-паролями.
4. Запустите: Windows — `powershell -ExecutionPolicy Bypass -File scripts/up.ps1`, Linux/macOS — `scripts/up.sh`. Скрипт собирает образы (первый раз — дольше: скачиваются базовые образы и зависимости Maven и npm) и ждёт, пока все сервисы будут готовы; в конце печатает адрес.
5. Откройте http://localhost:8080 и войдите в кабинет работодателя (`DEMO_EMPLOYER_EMAIL` и `DEMO_EMPLOYER_PASSWORD` из `.env`). Раздел администратора — http://localhost:8080/admin (`DEMO_ADMIN_EMAIL`, `DEMO_ADMIN_PASSWORD`). Для показа загрузите демо-сессии ([Демо-данные](#демо-данные)).

Остановка: `scripts/down.ps1` или `scripts/down.sh` (флаг `-Purge` / `--purge` удаляет базу данных).

## Демонстрация за 10 минут
Подготовка: стек запущен, демо-сессии загружены (`scripts/demo-reset.*` — с нуля, или `demo-seed` в работающий стек), вход работодателем выполнен; второе окно браузера — для кандидата.

| Время | Что показать | Где |
|---|---|---|
| 0:00–1:00 | Идея: кандидат решает практические задачи в редакторе, код исполняется в изолированной песочнице, работодатель получает балл, признаки достоверности и запись сессии | главная, кабинет работодателя |
| 1:00–3:30 | «Пригласить кандидата» → уровень → ссылка (копируется, по почте не отправляется). Во втором окне — ссылка: согласие на обработку данных, правила, разминка, задача в редакторе Monaco, «Запустить» — результат видимых тестов через несколько секунд | кабинет, окно кандидата |
| 3:30–5:30 | Отчёт «Демо: честное решение»: предварительный балл, по задачам «исправлено X из Y» и проверки «ничего не сломано», время, запуски, индикаторы с пояснениями, «Замечаний нет» | отчёт по сессии |
| 5:30–7:30 | «Демо: решение крупными вставками» и «Демо: перепечатывание со второго экрана»: «Серьёзные замечания», причины с уровнем, подсвеченные строки индикаторов ▲ | отчёты |
| 7:30–9:00 | «Воспроизвести сессию»: код набирается заново по шкале времени, видны вставки и всплески, график скорости набора | воспроизведение |
| 9:00–10:00 | Ограничения v1.0 (ниже) и что дальше: модели вместо правил, психометрическая калибровка балла, новые профили | — |

## Известные ограничения v1.0
- **Локальная версия.** Всё работает на одной машине в Docker Compose: без HTTPS, без облака, один runner. Приглашения не отправляются по почте — ссылку копирует работодатель. После завершения оценки кандидат результатов не видит.
- **Правиловые индикаторы.** Достоверность оценивают экспериментальные правила с порогами ([docs/indicators.md](docs/indicators.md)), а не обученные модели. Замечание — повод посмотреть воспроизведение, а не доказательство списывания.
- **Предварительный балл.** Доля исправленных скрытых тестов с весами по уровню задачи, до психометрической калибровки; задачи не выровнены по сложности статистически.
- **Один профиль.** Только Java-разработчик: 10 шаблонов задач по 5 вариантов и разминка ([tasks/java/CATALOG.md](tasks/java/CATALOG.md)).
- Песочница на Windows — только `runc`; gVisor (`runsc`) — только на Linux.
- Производительность проверена на 10 одновременных кандидатов; если все нажмут «Запустить» в одну секунду, последний ответ — около 14 с ([docs/performance.md](docs/performance.md)).

## Демо-данные
Чтобы отчёт и воспроизведение можно было показать сразу, есть три записанные сессии (`seed/demo-sessions`): честное решение, решение крупными вставками и перепечатывание со второго экрана.
- С нуля: `powershell -ExecutionPolicy Bypass -File scripts/demo-reset.ps1` или `scripts/demo-reset.sh` — **удаляет базу**, запускает стек и загружает демо-сессии в компанию демо-работодателя (`-Yes` / `--yes` — без вопроса). Балл и индикаторы появляются в течение минуты.
- В работающий стек: `docker compose --profile tools run --rm --build taskbank demo-seed /seed/demo-sessions` (уже загруженные пропускаются).
- Свою сессию в демо: администратор выгружает завершённую сессию — `GET /api/admin/sessions/{id}/demo-export?label=…` — и кладёт файл в `seed/demo-sessions`. Записать демо-сессии заново сценарием: `cd e2e && npm run record-demo` (на работающем стеке, 20–30 минут; оставляет приглашения «Запись: Демо: …»). Подробнее — [ADR 0014](docs/adr/0014-e2e-and-demo-data.md).

## Разработка
```bash
cd backend
mvn verify   # unit- и интеграционные тесты; нужен запущенный Docker (Testcontainers поднимает PostgreSQL 17)
```
E2E-тесты (Playwright) — против запущенного стека (`scripts/up.*`):
```bash
cd e2e
npm ci
npx playwright install chromium
npx playwright test   # несколько минут; создают приглашения и сессии с меткой «E2E …»
```
После `demo-seed` с переменной `GITS_DEMO_SEEDED=1` проверяются и демо-сессии (`tests/demo-seed.spec.ts`), без неё этот тест пропускается.
Нагрузочная проверка (10 кандидатов, запуски кода): `cd e2e && node load/run-load.mjs --candidates 10 --minutes 10` — методика и результаты в [docs/performance.md](docs/performance.md); оставляет приглашения «Нагрузка …».
Правила проекта для разработчиков и ИИ-ассистента — в [CLAUDE.md](CLAUDE.md), архитектурные решения — в [docs/adr](docs/adr), план разработки — в [docs/prompts/prompts-v1.0.md](docs/prompts/prompts-v1.0.md).

### Frontend
```bash
cd frontend
npm ci
npm start          # http://localhost:4200, /api проксируется на http://localhost:8080 (нужен запущенный стек)
npm run lint
npm test
npm run build
```
Редактор кода — Monaco (`monaco-editor`, версия закреплена): при сборке он копируется из node_modules в `assets/monaco` и загружается только оттуда, внешних запросов страница не делает. `/` — главная. Интерфейс кандидата — маршруты `/c/:token` (вход по ссылке), `/c/consent`, `/c/intro`, `/c/session`, `/c/done`; `/c/closed` — доступ закрыт (ссылка отозвана или оценка завершена), `/c/offline` — нет связи с сервером. Кабинет работодателя — `/login`, `/employer` (приглашения), `/employer/sessions/:id` (отчёт), `/employer/replay/:sessionTaskId` (воспроизведение сессии). Раздел администратора — `/admin` (ведёт на `/admin/tasks`), `/admin/tasks` (банк задач), `/admin/tasks/:variantId` (вариант со всеми файлами), `/admin/sessions` (сессии, пересчёт, выгрузка для исследования).
