# ADR 0011. Интерфейс кабинета работодателя

**Статус:** принято. **Дата:** 2026-09-28. **Этап:** P13.

## Контекст
P13 — интерфейс работодателя в Angular поверх API из P09 и P12: вход, список приглашений с результатами, отчёт по сессии. Демо показывают на ноутбуке (ширина от 1280 px), часто в тот момент, когда кандидат ещё проходит оценку в соседнем окне.

## Решения
| Вопрос | Решение | Обоснование |
|---|---|---|
| Доступ к страницам | Guard `employerGuard` спрашивает `GET /api/auth/me`. Без сессии — `/login?returnUrl=…`, после входа возврат на ту же страницу. Возврат только на пути `/employer…`. Сервер недоступен — та же страница входа с пояснением о связи | Нельзя увести пользователя на чужой сайт через параметр адреса (open redirect) |
| Администратор | Кабинет работодателя открывается только для роли EMPLOYER. Администратор, вошедший на этой странице, сразу выходит обратно (шапки с «Выйти» у него здесь нет) и видит пояснение; свой раздел у него появится в P15 | API `/employer/**` для ADMIN закрыт (403), пустой кабинет только запутал бы |
| Конец сессии | Если сессия закончилась, пока страница открыта (истекла, api перезапущен), первый же ответ 401 от `/api/employer/**` или `/api/invites` (перехватчик `sessionLostInterceptor`) ведёт на вход с пояснением «Сессия закончилась» и возвратом на ту же страницу | Иначе страница бесконечно показывала бы «Не удалось загрузить» |
| Выход | Пользователь считается вышедшим, только когда сервер ответил на `POST /auth/logout`; ответ 403 (устаревший CSRF-токен) — повтор со свежим токеном. Нет связи — «Не удалось выйти», пользователь остаётся в кабинете | На общем демо-ноутбуке живая сессия не должна остаться за «вышедшим» пользователем |
| CSRF | Общий `CsrfService`: кандидат и работодатель берут cookie `XSRF-TOKEN` одинаково; перед входом токен всегда запрашивается заново | Один механизм; токен прежней сессии мог устареть |
| Уровень доверия | Цветная метка и текст: «Замечаний нет», «Есть замечания», «Серьёзные замечания» | Цвет не единственный признак (доступность, печать в ч/б) |
| Скрытые тесты | Текст совпадает с тем, как их считает балл: «X из Y»; «0: код не скомпилировался», «0: превышено время выполнения», «0: скрытые тесты не выполнились» — в балле 0; «Не проверено: сбой проверки» — ошибка runner или задача, исключённая из балла; «Проверяется…» — проверка ещё идёт | Работодатель видит то же, что учтено в балле |
| Индикаторы | Русское название (подпись во фронтенде) и пояснение, которое сервер уже формирует на русском. Порядок фиксирован, неизвестные новые индикаторы показываются под своим именем. Сработавшие правила — отдельным списком; у разминки не показываются, потому что в оценку она не входит | Тексты с порогами живут в одном месте (сервер, docs/indicators.md) |
| Компетенции | В отчёте добавлено поле `competencyTitles`: русские названия из `tasks/competencies.yaml` смонтированного банка задач в том же порядке, что `competencies`. Без банка или для неизвестного кода показывается код | Работодателю нужны понятные названия; справочник уже есть в банке задач, в БД его нет |
| Обновление данных | Список приглашений обновляется раз в 20 с, пока вкладка видна, и сразу при возвращении на вкладку. Отчёт без балла (сессия идёт или решения проверяются) — раз в 15 с до появления балла, тоже только при видимой вкладке. Неудачное обновление оставляет прежние данные на экране | Демо-сценарий «кандидат в соседнем окне»; без WebSocket (ADR 0001) |
| Итоговый код | Monaco только для чтения, вкладка на файл, модели без URI | Тот же редактор, что у кандидата; несколько просмотрщиков на странице не конфликтуют |
| Ссылка приглашения | Показывается один раз, в окне после создания (пока приглашение создаётся, окно не закрывается — иначе ссылка потерялась бы), с кнопкой «Копировать» (Clipboard API, запасной вариант — `execCommand`, иначе подсказка «нажмите Ctrl+C») | Токен не хранится на сервере (ADR 0003) — показать ссылку повторно нельзя |
| Воспроизведение | Кнопка «Воспроизвести сессию» ведёт на `/employer/replay/:sessionTaskId`; в P14 там проигрыватель ([ADR 0012](0012-session-replay.md)). У задачи, которую кандидат не открывал (`startedAt` пуст; при завершении сессии она отправляется как есть), кнопка неактивна, а время — «не открыта» | Маршрут фиксируется сейчас, проигрыватель — P14, ADR 0012 |

## Последствия
- Если `tasks/competencies.yaml` поменяется, названия в отчёте обновятся после перезапуска api.
- Поле `competencyTitles` — добавление к ответу API, существующие клиенты не ломаются.
- Отозвать можно только неиспользованное приглашение (CREATED); кнопка показывается только у него.
