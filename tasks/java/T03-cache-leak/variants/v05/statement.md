# Кэш сессий абонентов

Шлюз мобильного интернета при каждом пакете данных проверяет сессию абонента. Сессии хранятся в распределённом хранилище (`SessionStore`); чтобы не обращаться к нему на каждый пакет, шлюз кэширует сессии в `SessionCache`. У кэша есть ограничение по числу сессий и срок жизни записи. Для отдела эксплуатации кэш ведёт статистику: суммарные попадания и промахи, а также число обращений к каждой сессии, по которому строится список самых активных абонентов `mostActive(n)`.

## Что наблюдается
Шлюз перезапускается раз в несколько дней из-за исчерпания памяти, хотя `size()` кэша никогда не превышает заданную ёмкость. Дамп памяти показывает миллионы строк с идентификаторами сессий, давно завершившихся или вытесненных из кэша. Кроме того, в `mostActive` попадают сессии, которых уже нет в кэше.

## Что нужно сделать
Устраните утечку памяти в `SessionCache`. Статистика по конкретной сессии должна храниться, только пока сессия находится в кэше, а `mostActive` — возвращать только сессии из кэша. Суммарные счётчики `hits()` и `misses()` должны оставаться точными за всё время работы.

## Ограничения
- Публичные методы и их сигнатуры менять нельзя.
- `Session` и `SessionStore` доступны только для чтения.
- Текущее время берётся только из переданных часов `Clock`; кэш используется из одного потока.
- Ограничение ёмкости, срок жизни и загрузка сессии из хранилища один раз на промах должны работать как раньше.

## Как будет проверено
Видимые тесты проверяют кэширование и статистику. Скрытые тесты проверяют объём статистики на большом числе сессий и поведение при вытеснении и истечении срока.
