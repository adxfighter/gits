# Дубликаты в списке учебной группы

Деканат формирует списки учебных групп в `StudyGroup`. Студент идентифицируется объектом `StudentId`: кодом университета и номером зачётной книжки. Два объекта `StudentId` с одинаковыми кодом и номером обозначают одного и того же студента, даже если созданы в разных частях системы, например при импорте из приёмной комиссии и из системы расписания.

## Что наблюдается
После объединения данных из нескольких систем в списках групп появились дубликаты: один и тот же студент числится в группе дважды, и `size()` группы больше реального числа студентов. Проверка `contains` для студента, импортированного из другой системы, иногда возвращает `false`, хотя студент в группе есть. Метод `equals` в `StudentId` при этом реализован и в отладчике возвращает `true` для таких объектов.

## Что нужно сделать
Исправьте `StudentId`, чтобы одинаковые студенты не дублировались в группе и находились в ней независимо от того, какой системой создан объект.

## Ограничения
- `StudyGroup` доступен только для чтения.
- Публичный API `StudentId` менять нельзя; смысл равенства — код университета и номер зачётки — сохраняется.

## Как будет проверено
Видимые тесты проверяют сравнение студентов. Скрытые тесты проверяют поведение группы при импорте данных из разных систем.
