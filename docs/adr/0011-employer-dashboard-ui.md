# ADR 0011. Интерфейс кабинета работодателя

**Статус:** принято. **Дата:** 2026-09-28. **Этап:** P13.

## Контекст
P13 — интерфейс работодателя в Angular поверх API из P09 и P12: вход, список приглашений с результатами, отчёт по сессии. Демо показывают на ноутбуке (ширина от 1280 px), часто в тот момент, когда кандидат ещё проходит оценку в соседнем окне.

## Решения
| Вопрос | Решение | Обоснование |
|---|---|---|
| Доступ к страницам | Guard `employerGuard` спрашивает `GET /api/auth/me`. Без сессии — `/login?returnUrl=…`, после входа возврат на ту же страницу. Возврат только на пути `/employer…` | Нельзя увести пользователя на чужой сайт через параметр адреса (open redirect) |
| Администратор | Кабинет работодателя открывается только для роли EMPLOYER. Администратор видит на странице входа пояснение; свой раздел у него появится в P15 | API `/employer/**` для ADMIN закрыт (403), пустой кабинет только запутал бы |
| CSRF | Общий `CsrfService`: кандидат и работодатель берут cookie `XSRF-TOKEN` одинаково; перед входом токен всегда запрашивается заново | Один механизм; токен прежней сессии мог устареть |
| Уровень доверия | Цветная метка и текст: «Замечаний нет», «Есть замечания», «Серьёзные замечания» | Цвет не единственный признак (доступность, печать в ч/б) |
| Индикаторы | Русское название (подпись во фронтенде) и пояснение, которое сервер уже формирует на русском. Порядок фиксирован, неизвестные новые индикаторы показываются под своим именем. Сработавшие правила — отдельным списком; у разминки не показываются, потому что в оценку она не входит | Тексты с порогами живут в одном месте (сервер, docs/indicators.md) |
| Компетенции | В отчёте добавлено поле `competencyTitles`: русские названия из `tasks/competencies.yaml` смонтированного банка задач в том же порядке, что `competencies`. Без банка или для неизвестного кода показывается код | Работодателю нужны понятные названия; справочник уже есть в банке задач, в БД его нет |
| Обновление данных | Список приглашений обновляется раз в 20 с, пока вкладка видна. Отчёт без балла (сессия идёт или решения проверяются) — раз в 15 с до появления балла. Неудачное обновление оставляет прежние данные на экране | Демо-сценарий «кандидат в соседнем окне»; без WebSocket (ADR 0001) |
| Итоговый код | Monaco только для чтения, вкладка на файл, модели без URI | Тот же редактор, что у кандидата; несколько просмотрщиков на странице не конфликтуют |
| Ссылка приглашения | Показывается один раз, в окне после создания, с кнопкой «Копировать» (Clipboard API, запасной вариант — `execCommand`, иначе подсказка «нажмите Ctrl+C») | Токен не хранится на сервере (ADR 0003) — показать ссылку повторно нельзя |
| Воспроизведение | Кнопка «Воспроизвести сессию» ведёт на `/employer/replay/:sessionTaskId`; до P14 там заглушка | Маршрут фиксируется сейчас, проигрыватель — в P14 |

## Последствия
- Если `tasks/competencies.yaml` поменяется, названия в отчёте обновятся после перезапуска api.
- Поле `competencyTitles` — добавление к ответу API, существующие клиенты не ломаются.
- Отозвать можно только неиспользованное приглашение (CREATED); кнопка показывается только у него.
