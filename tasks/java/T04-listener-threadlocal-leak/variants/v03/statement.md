# Контекст клиента в обработке запросов

Интернет-банк обрабатывает запросы в пуле потоков. `RequestProcessor.handle(request, handler)` помещает клиента, от имени которого пришёл запрос, в `SecurityContext` — хранилище на `ThreadLocal`. Затем он вызывает обработчик, который узнаёт текущего клиента через `SecurityContext.currentClient()`. Анонимные запросы (просмотр курсов валют, адреса отделений) приходят без клиента.

## Что наблюдается
Служба безопасности зафиксировала инцидент: в журнале аудита анонимные запросы на просмотр курсов записаны от имени реальных клиентов, прошедших авторизацию незадолго до этого. Воспроизвести проблему удалось только под нагрузкой, когда потоки пула повторно используются. В отдельных случаях после ошибки в обработке платежа следующий анонимный запрос в том же потоке «видел» клиента из упавшего запроса.

## Что нужно сделать
Исправьте `RequestProcessor`, чтобы контекст клиента существовал только во время обработки своего запроса — и при успешной обработке, и при ошибке.

## Ограничения
- `SecurityContext` и `BankRequest` доступны только для чтения.
- Публичные методы и их сигнатуры менять нельзя.
- Исключение обработчика должно по-прежнему доходить до вызывающего кода.

## Как будет проверено
Видимые тесты проверяют обработку запросов. Скрытые тесты выполняют последовательности авторизованных и анонимных запросов, в том числе с ошибками, в пуле с повторно используемым потоком.
