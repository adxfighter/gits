# Кредитный скоринг по трём бюро

Решение по заявке на кредит принимает `CreditScoring.decide(applicantId)`. Сервис асинхронно запрашивает скоринговый балл заявителя в нескольких кредитных бюро (`CreditBureau.score`) и возвращает `CompletableFuture<Decision>`.

Правила решения:
- учитываются баллы бюро, которые ответили не позже таймаута `bureauTimeout` с момента запроса;
- если учтено меньше двух баллов — `MANUAL_REVIEW`;
- иначе при среднем балле не ниже `approvalThreshold` — `APPROVED`, ниже — `REJECTED`;
- в решении перечислены учтённые баллы по имени бюро.

## Что наблюдается
- Одно из бюро периодически отвечает по несколько минут, и все заявки в это время «висят».
- Когда бюро отвечает ошибкой, заявка падает с ошибкой вместо решения.
- После первой попытки исправления (таймаут на ответ бюро) другая команда пожаловалась: их сервис получает ответы бюро через общий кэш тех же future, и эти future стали завершаться ошибкой таймаута по вине скоринга.
- Клиент одного из бюро иногда бросает исключение прямо из `score`, не возвращая future.

## Что нужно сделать
Исправьте `CreditScoring.decide` по правилам решения. Бюро, которое ответило ошибкой, не ответило за таймаут или бросило исключение прямо из `score`, исключается из решения. Future, возвращённый бюро, нельзя завершать, отменять или менять: им пользуются и другие сервисы.

## Ограничения
- `CreditBureau` и `Decision` доступны только для чтения; конструктор и сигнатура `decide` не меняются.
- Ответ бюро, пришедший после таймаута, в решении не учитывается.

## Как будет проверено
Тесты используют бюро-заглушки, ответ которых тест завершает вручную, или которые не отвечают вовсе, и короткий таймаут (100 мс). Видимые тесты проверяют случай, когда ответили все бюро. Скрытые тесты проверяют медленные бюро, ошибки (в том числе исключение из `score`), ответы после таймаута и то, что future бюро остаётся нетронутым.
