# ADR 0012. Воспроизведение сессии

**Статус:** принято. **Дата:** 2026-09-28. **Этап:** P14.

## Контекст
Воспроизведение — главная демонстрационная функция для работодателя: увидеть, как кандидат писал код, где вставлял, уходил со страницы, запускал тесты. Данные уже есть: `GET /api/employer/session-tasks/{id}/replay` (P09) отдаёт файлы, которые видел кандидат, запуски и события телеметрии (ADR 0007). Требование P14: сессия 30 минут с 20 000 событий перематывается без задержек.

## Решения
| Вопрос | Решение | Обоснование |
|---|---|---|
| Где восстанавливать текст | В браузере (`SessionRecording`, `core/replay`): файлы начинаются с `initialFiles`, события `edit` применяются в записанном порядке | Сервер отдаёт сырые события постранично; восстановление на клиенте не нагружает api и позволяет мгновенно перематывать |
| Отмена и повтор | Отдельной логики нет: Ctrl+Z и Ctrl+Y записаны как обычные изменения (`isUndo`, `isRedo`) с диапазоном и текстом | Монако сообщает об отмене тем же событием изменения, что и о наборе |
| Несколько изменений одного события (несколько курсоров) | Применяются подряд в записанном порядке | Monaco перечисляет их от конца документа к началу, каждое — относительно текста до события |
| Перемотка | Контрольные точки состояния каждые 500 событий; кадр строится от ближайшей точки, не больше 499 событий после неё | Тест: 20 000 событий, в среднем меньше 5 мс на перемотку |
| Время | `t` событий, сделанное неубывающим; порядок применения — порядок записи (по `seq` и внутри пакета) | Время из телеметрии не идёт назад (ADR 0007), но порядок изменений важнее времени |
| Активный файл | Файл последнего `edit`, `cursor` или `select`; в начале — файл первого такого события, без таких событий — первый редактируемый файл | Разминка начинается с `Typing.txt`, хотя первым в списке идёт класс части 2 |
| Проверка записи | Восстановленные редактируемые файлы сравниваются с итоговым кодом отчёта: «совпадает с итоговым» или «запись неполная» | Честно: если страница перезагрузилась до автосохранения или телеметрия потерялась, воспроизведение приблизительное |
| Запуски на шкале | Место — нажатие `run`/`submit` в телеметрии (шкала `t`), результат — запуск сервера того же вида по порядку: n-е нажатие — n-й запуск. Запуск без нажатия (отправка платформой при завершении сессии — «Отправлено при завершении сессии», или нажатие, потерянное вместе с телеметрией) ставится по `offsetMs` сервера, но не позже конца записи; запуск без `offsetMs` на шкалу не попадает. Шкала длится до последнего события | `offsetMs` включает время, пока страница была закрыта, и работу над другими задачами: иначе запись задачи сжалась бы в начало шкалы | Время сервера и шкала `t` расходятся после перезагрузки страницы: время, пока страница была закрыта, в `t` не входит |
| Уход со страницы | Интервалы считаются по правилу индикатора `focusLoss`: от `blur` или скрытой вкладки до `focus` и видимой вкладки или любой активности (правка, курсор, выделение, вставка, запуск, автодополнение). Нажатий клавиш и копирования в данных воспроизведения нет, поэтому интервал может закончиться чуть позже, чем в индикаторе; уходы нулевой длины считаются, но на шкале не видны | Шкала и индикатор отчёта говорят почти одно и то же |
| Скорость набора | Символы правок с `source: typing` (без отмены и повтора) в секунду, в среднем за последние 5 с, по целым секундам записи; вставки и автодополнение отмечены отдельно | Нажатия клавиш в воспроизведение не передаются, поэтому считаются символы правок. В отличие от `burstMax` (ADR 0008) сюда входят автоотступы и автозакрытие скобок — в задачах график может быть выше `burstMax` |
| Проигрыватель | `requestAnimationFrame`, время записи = прошедшее время × скорость (1×, 2×, 5×, 10×, 20×; по умолчанию 5×); «пропускать паузы длиннее N с» (N от 1 до 600, по умолчанию включено, 10 с) переносит к секунде до следующего события телеметрии. Метка запуска, поставленная по `offsetMs` внутри длинной паузы, может быть пропущена | Длинная разминка или уход на час не заставляют ждать |
| Редактор | Monaco только для чтения, модель на файл; новый кадр меняет только отличающуюся середину текста, поэтому прокрутка не прыгает. Курсор кандидата — отдельная отметка. Можно смотреть другой файл и вернуться к «Следовать за кандидатом» | Тот же редактор, что у кандидата |
| Данные | Все страницы API по 200 пакетов (`EmployerApi.replay`), затем отчёт сессии — для названия, итоговых индикаторов и итогового кода. В ответ воспроизведения добавлен `sessionId` — путь назад к отчёту | Без отчёта воспроизведение тоже работает, только без названия и проверки |
| Фикстуры тестов | Три реальные записи со стенда (разминка с двумя файлами и отменой, задача со вставками и вырезанием, короткая задача) в `core/replay/recordings`; восстановленный текст совпадает с итоговым кодом на 100% | Критерий приёмки P14; записи сделаны командой на тестовом стенде, персональных данных нет |

## Последствия
- Сессии, начатые до переделки разминки (файл `Typing.java`), воспроизводятся неточно: файлы варианта в банке задач с тех пор изменились на месте, а воспроизведение берёт их текущее содержимое. Для новых сессий это не так, пока варианты в банке не меняются после выдачи.
- В скрытой вкладке браузер не даёт кадров анимации, и проигрывание стоит — это нормально.
- Нажатия клавиш в воспроизведение не передаются (P09), поэтому график скорости считает символы, а не нажатия.
- Красная вставка («не из задачи») — как в индикаторе `externalPastes`: `ownCode: false`, от 10 непробельных символов и не отменённая сразу. Индикатор дополнительно не считает вставку, длина которой совпала с предыдущим копированием (копирование в воспроизведение не передаётся), поэтому красных меток может быть чуть больше.
