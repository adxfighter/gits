# Управление коечным фондом больницы

Сервис `BedManagementService` управляет размещением пациентов по отделениям больницы:
- `transfer(from, to)` — переводит пациента, дольше всех находящегося в отделении `from`, в отделение `to`, если там есть свободная койка;
- `redistribute(wards)` — перераспределяет пациентов между несколькими отделениями, чтобы загрузка отличалась не более чем на одного пациента;
- `totalPatients(wards)` — согласованная сводка для дежурного администратора: общее число пациентов в перечисленных отделениях.

Запросы приходят параллельно из приёмного покоя, от лечащих врачей и из ночной задачи перераспределения. Каждое отделение (`Ward`) защищает свои данные собственным монитором.

## Что наблюдается
Несколько раз в неделю система размещения зависает целиком, пока её не перезапустят. Чаще всего это происходит ночью, когда задача перераспределения работает одновременно с переводами. Анализ дампов показал взаимную блокировку, причём в цепочке ожидания участвуют разные методы. Порядок отделений в списке, который передаётся в `redistribute` и `totalPatients`, зависит от вызывающей стороны и не упорядочен.

## Что нужно сделать
Устраните взаимные блокировки во всех операциях. Перевод и перераспределение должны оставаться атомарными, сводка — согласованной, вместимость отделений не должна нарушаться ни в какой момент.

## Ограничения
- Публичные методы `BedManagementService` и `Ward` и их сигнатуры менять нельзя; внутреннее устройство классов можно менять.
- Класс `Patient` доступен только для чтения.
- Поведение операций в одном потоке должно остаться прежним.

## Как будет проверено
Видимые тесты проверяют операции в одном потоке. Скрытые тесты запускают переводы, перераспределение и сводки одновременно из нескольких потоков с ограничением времени.
