# Лимиты партнёрского API по клиентам

Партнёры магазина обращаются к API каталога. У каждого партнёра (ключ — `clientId`) свой лимит: ведро `TokenBucket` ёмкостью `capacity`, которое пополняется со скоростью `tokensPerSecond`. `ApiRateLimiter.tryAcquire(clientId)` берёт один токен из ведра клиента и создаёт ведро при первом обращении клиента. Новое ведро заполнено.

`TokenBucket` проверен и потокобезопасен. `ApiRateLimiter` вызывается из многих потоков веб-сервера одновременно.

## Что наблюдается
- Новые партнёры в первые секунды после подключения успевают сделать больше запросов, чем позволяет их лимит: иногда вдвое больше.
- Под нагрузкой изредка случается, что лимит клиента «обнуляется» посреди работы, а однажды поток веб-сервера завис внутри `tryAcquire`.

## Что нужно сделать
Исправьте `ApiRateLimiter`, чтобы у каждого клиента было ровно одно ведро, а лимит соблюдался при любом числе одновременных запросов.

## Ограничения
- `TokenBucket` доступен только для чтения.
- Конструктор и `tryAcquire(clientId)` остаются прежними.
- Запросы разных клиентов не должны ждать друг друга на общей блокировке.

## Как будет проверено
Тесты управляют временем через `nanoClock`. Видимые тесты проверяют лимиты последовательных запросов. Скрытые тесты одновременно из нескольких потоков отправляют запросы от большого числа новых клиентов и проверяют, что успешных запросов у каждого клиента ровно столько, сколько позволяет его ведро. Также проверяется, что зависший запрос одного клиента не задерживает запросы других.
