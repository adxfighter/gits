# Контекст врача при консилиумах

Медицинская информационная система записывает каждое действие с картой пациента от имени врача. Текущий врач хранится в `DoctorContext` (на `ThreadLocal`), а код выполняется от его имени через `DoctorContext.runAs(doctor, action)`. Если во время приёма лечащему врачу нужно мнение коллеги, `ConsultationService` вызывает `runAs` для консультанта внутри действия лечащего врача — контексты вкладываются друг в друга. Запросы обрабатываются в пуле потоков.

## Что наблюдается
Юристы клиники обнаружили в журнале действий записи без врача: назначения, сделанные лечащим врачом **после** консультации коллеги в рамках того же приёма. Сервис аудита при этом выдаёт ошибку «действие без врача». Кроме того, если консультация завершается ошибкой, следующий запрос в том же потоке иногда выполняется от имени консультанта.

## Что нужно сделать
Исправьте `DoctorContext`, чтобы после выхода из вложенного `runAs` снова действовал внешний врач, после выхода из внешнего — не действовал никто, и это выполнялось при любом исходе действия, включая исключение.

## Ограничения
- `Doctor` и `ConsultationService` доступны только для чтения.
- Публичные методы `DoctorContext` и их сигнатуры менять нельзя.
- Исключение действия должно доходить до вызывающего кода.

## Как будет проверено
Видимые тесты проверяют выполнение действий от имени врача. Скрытые тесты проверяют вложенные и многоуровневые контексты, исключения и повторное использование потоков пула.
