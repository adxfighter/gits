# GITS — правила проекта

## Что это
Локальная демо-версия v1.0 платформы оценки практических навыков Java-разработчиков.
Запуск: scripts/up.ps1 (Windows) или scripts/up.sh (Linux/macOS). UI: http://localhost:8080.

## Стек
Backend: Java 21, Spring Boot 3.5, Maven, PostgreSQL 17, Flyway, Spring Data JPA, Testcontainers.
Frontend: Angular 21 (standalone, signals), Monaco Editor (локальные ассеты), SCSS.
Песочница: образ gits-sandbox-java (JDK 21, JUnit 5, AssertJ, Mockito).

## Модули и границы
- gits-core: доменные сущности, репозитории, общие DTO. Не зависит от web.
- gits-api: REST-контроллеры, безопасность, Flyway-миграции (единственный владелец схемы БД).
- gits-runner: исполнитель кода. Единственный модуль с доступом к Docker. Не имеет REST API.
- gits-taskbank: CLI валидатора банка задач и загрузчик задач в БД.
- frontend не содержит бизнес-логики оценки; всё считается на backend.

## Жёсткие правила безопасности
- Скрытые тесты и эталонные решения никогда не отдаются через API кандидату. Любой новый endpoint, возвращающий задачу, должен иметь тест, проверяющий отсутствие этих данных.
- Контейнер песочницы: --network=none, read-only rootfs, tmpfs /work, лимиты памяти/CPU/pids, непривилегированный пользователь, таймаут, удаление после запуска. Не ослаблять без ADR.
- Никаких секретов в коде и тестах; только через .env. Пароли — BCrypt.
- Телеметрия собирается только после согласия кандидата и только внутри страницы оценки. Символы нажатых клавиш не логируются — только категория клавиши.

## Стиль
- Код, идентификаторы, коммиты — на английском. Интерфейс, условия задач, документация — на русском.
- Backend: конструкторная инъекция, record для DTO, без Lombok, ошибки — Problem Details (RFC 9457).
- Frontend: standalone-компоненты, signals для состояния, строгая типизация, без any.
- Каждое изменение сопровождается тестами. Интеграционные тесты БД — Testcontainers.

## Проверка перед завершением задачи
1. cd backend && mvn -q verify
2. cd frontend && npm run lint && npm test && npm run build
3. docker compose up --build -d и ручная проверка изменённого сценария
Не сообщай, что задача выполнена, если какая-то проверка не прошла.
