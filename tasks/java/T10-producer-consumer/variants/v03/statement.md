# Остановка платёжного конвейера

Платёжный шлюз передаёт платежи в `PaymentPipeline.submit(payment)` из нескольких потоков. Платежи попадают в ограниченную очередь ёмкостью `queueCapacity` и обрабатываются несколькими потоками-потребителями. Если очередь заполнена, `submit` ждёт свободного места — так шлюз замедляется вместе с процессингом.

`submit` возвращает `true`, если платёж принят, и `false`, если конвейер уже останавливается. Остановка `stop(timeout)`:
- после начала остановки новые платежи не принимаются, а ожидающие места в очереди `submit` возвращают `false`;
- каждый принятый платёж (`submit` вернул `true`) обрабатывается ровно один раз;
- непринятые платежи не обрабатываются — шлюз вернёт их отправителю;
- `stop` возвращает `true`, если потребители завершились до истечения таймаута.

## Что наблюдается
- Во время остановки под нагрузкой потоки шлюза навсегда зависают внутри `submit`, и перезапуск приходится делать через `kill -9`.
- Сверка после остановки находит принятые платежи, которые не были обработаны.

## Что нужно сделать
Исправьте `PaymentPipeline`, чтобы остановка соответствовала правилам при любом числе производителей и потребителей.

## Ограничения
- `Payment` доступен только для чтения; конструктор и публичные методы `PaymentPipeline` не меняются.
- Потоки конвейера остаются daemon-потоками. `submit` не должен занимать процессор активным ожиданием.

## Как будет проверено
Видимые тесты проверяют обработку и остановку без нагрузки. Скрытые тесты останавливают конвейер, пока четыре производителя ждут места в заполненной очереди, и сверяют принятые и обработанные платежи.
