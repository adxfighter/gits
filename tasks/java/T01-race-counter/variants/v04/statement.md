# Сводка потребления электроэнергии по счётчикам

Энергосбытовая компания получает показания интеллектуальных счётчиков от концентраторов данных. Каждое показание — это прирост потребления в ватт-часах за интервал. Концентраторы отправляют показания параллельно, и сервис вызывает `ConsumptionAggregator.add(reading)` из шестнадцати потоков. Раз в час диспетчерская запрашивает `snapshot()` — потребление по каждому счётчику — и `total()` для сверки с данными подстанции.

## Что наблюдается
- Суммарное потребление по счётчикам стабильно меньше, чем зафиксировано на подстанции.
- Иногда запрос сводки завершается ошибкой `ConcurrentModificationException`, диспетчер повторяет запрос вручную.
- В редких случаях после пиковой нагрузки отдельные счётчики пропадают из сводки.

## Что нужно сделать
Исправьте `ConsumptionAggregator`, чтобы потребление учитывалось без потерь при параллельном поступлении показаний, а сводку и итог можно было запрашивать в любой момент, в том числе во время записи. Показания разных счётчиков не должны ждать друг друга без необходимости.

## Ограничения
- Публичные методы и их сигнатуры менять нельзя.
- Класс `MeterReading` доступен только для чтения.
- Проверка показаний должна работать как раньше.

## Как будет проверено
Видимые тесты проверяют поведение в одном потоке. Скрытые тесты проверяют точность учёта при параллельной записи и чтение сводки во время записи.
