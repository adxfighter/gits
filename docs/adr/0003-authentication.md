# ADR 0003. Аутентификация работодателя и кандидата

**Статус:** принято. **Дата:** 2026-09-27.

## Решения
| Вопрос | Решение | Почему |
|---|---|---|
| Работодатель и админ | JSON-вход `POST /api/auth/login`, контекст Spring Security в HTTP-сессии (cookie `JSESSIONID`, HttpOnly, SameSite=Lax); при входе сессия пересоздаётся | Простая модель для SPA; защита от фиксации сессии |
| Кандидат | Отдельная цепочка фильтров для `/api/candidate/**` без сессии: подписанная HMAC-SHA256 cookie `GITS_CANDIDATE` (path `/api/candidate`, HttpOnly, 12 ч) с id приглашения и версией принятого согласия | Работодатель и кандидат могут одновременно работать в одном браузере на демо; ссылка кандидата не даёт доступа к API работодателя |
| Ключ подписи | `GITS_CANDIDATE_SECRET`; если не задан — случайный ключ на запуск (предупреждение в логе) | Демо работает без настройки; в стабильной среде ключ задаётся |
| Ссылка-приглашение | Токен 32 байта (base64url, 43 символа), в БД — только SHA-256; срок 7 дней | Утечка базы не даёт рабочих ссылок |
| Согласие | Все endpoint'ы кандидата, кроме `/candidate/enter`, `/candidate/me`, `/candidate/consent`, требуют принятого согласия текущей версии (authority `CONSENT_GIVEN`); после принятия cookie перевыпускается | Телеметрия и задачи недоступны до согласия |
| CSRF | Cookie `XSRF-TOKEN` (path `/`, читается JS) + заголовок `X-XSRF-TOKEN`, в обеих цепочках; `GET /api/auth/csrf` выдаёт cookie | Стандартная схема Angular; path `/` нужен, чтобы SPA на `/` видело cookie |
| Ошибки | Problem Details (RFC 9457) с текстом на русском; 401 без редиректов | Удобно для SPA |
| Лимиты | Вход работодателя — 10/мин на IP, вход по ссылке — 20/мин на IP, в памяти процесса; реальный IP за nginx — `server.forward-headers-strategy: native` | Защита от перебора паролей и токенов на одном экземпляре api |
| Демо-аккаунты | Создаются при старте из `DEMO_*`; пароль обновляется при изменении переменной | Воспроизводимый запуск демо |

## Проверка
- Интеграционные тесты (MockMvc + PostgreSQL в Testcontainers): вход, выход, 401/403, CSRF, лимиты, изоляция компаний, согласие, повторное использование и истечение ссылки, подделка cookie, отсутствие паролей и токенов в логах.
- `scripts/smoke-auth.sh` — тот же сценарий через nginx с настоящими cookie, в том числе одновременная работа ролей в одном браузере; запускается в CI.
