# Запись детализации звонков

Коммутаторы передают записи о звонках (CDR) в `CdrWriter.accept(record)` из нескольких потоков. Писатель сохраняет записи в хранилище `CdrStore` на собственном пуле из нескольких потоков, чтобы не задерживать коммутаторы. Сохранение одной записи может занимать заметное время: хранилище иногда отвечает медленно.

Правила закрытия `close(timeout)`:
- после начала закрытия новые записи не принимаются (`accept` бросает `IllegalStateException`);
- все записи, принятые до закрытия, сохраняются ровно один раз, в том числе те, что ещё ждут своей очереди;
- `close` возвращает `true`, если все принятые записи сохранены до истечения таймаута, иначе `false`.

Записи о звонках — основание для выставления счетов абонентам, их потеря означает прямые убытки.

## Что наблюдается
После каждого планового перезапуска биллинг недосчитывается нескольких тысяч звонков, принятых писателем в последние секунды. В журнале есть ошибки хранилища о прерванной записи.

## Что нужно сделать
Исправьте закрытие `CdrWriter` по описанным правилам.

## Ограничения
- `CallRecord` и `CdrStore` доступны только для чтения; конструктор и публичные методы `CdrWriter` не меняются.
- Потоки пула остаются daemon-потоками.

## Как будет проверено
Тесты используют хранилище-заглушку, которое тест может задержать. Видимые тесты проверяют сохранение и закрытие без нагрузки. Скрытые тесты закрывают писателя, пока в пуле есть незавершённые и ожидающие записи от двух производителей, и сверяют сохранённые записи.
