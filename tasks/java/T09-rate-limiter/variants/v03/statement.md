# Лимит платёжных операций

Процессинговый центр банка ограничивает частоту операций по терминалам мерчанта: `PaymentLimiter(capacity, tokensPerSecond, nanoClock)`. Это token bucket:
- в ведре не больше `capacity` токенов, в начале оно заполнено;
- токены пополняются равномерно со скоростью `tokensPerSecond`, дробные доли не теряются;
- `tryAcquire()` берёт один токен, если он есть;
- `available()` возвращает число целых токенов.

Ограничитель вызывается одновременно из многих потоков авторизационного сервиса.

## Что наблюдается
Служба мониторинга регулярно фиксирует превышение лимита: за секунду мерчант проводит больше операций, чем `capacity + tokensPerSecond`. В нагрузочном тесте на 8 потоках с исчерпанием ведра пропускается на 5–10 % больше операций, чем должно. На одном потоке превышения нет.

## Что нужно сделать
Сделайте `PaymentLimiter` потокобезопасным: за любой интервал число выданных токенов должно точно соответствовать ёмкости и пополнению.

## Ограничения
- Конструктор и публичные методы остаются прежними; `tryAcquire` не должен ждать появления токена.
- Точность пополнения (без потери дробных долей) нужно сохранить.

## Как будет проверено
Тесты управляют временем через `nanoClock`. Видимые тесты проверяют ограничитель в одном потоке. Скрытые тесты запускают 8 потоков одновременно, в том числе при пополнении во время нагрузки, и сверяют число выданных токенов с точным ожидаемым значением.
