# Приём телеметрии счётчиков

Сервис приёма телеметрии получает показания счётчиков из двух каналов (MQTT и HTTP): оба вызывают `TelemetryIngest.submit(reading)`. Показания складываются в ограниченную очередь ёмкостью `queueCapacity` и обрабатываются несколькими потоками-потребителями. Если очередь заполнена, `submit` ждёт свободного места.

Показания приходят неравномерно: бывают паузы в несколько секунд, а потом резкий всплеск.

Правила:
- потребители работают с момента создания до закрытия и ждут новых показаний, даже когда очередь пуста;
- `close(timeout)` запрещает приём (`submit` бросает `IllegalStateException`), дожидается обработки всех принятых показаний и завершения потребителей; возвращает `true`, если это произошло до таймаута;
- каждое принятое показание обрабатывается ровно один раз;
- ошибка обработчика на одном показании не останавливает потребителя.

`close` вызывается после того, как каналы перестали передавать показания.

## Что наблюдается
- После утренней паузы в приёме показания перестают обрабатываться совсем, хотя сервис продолжает их принимать.
- Иногда `close` возвращает `false` по таймауту, хотя все показания уже обработаны.

## Что нужно сделать
Исправьте `TelemetryIngest` по описанным правилам.

## Ограничения
- `Reading` доступен только для чтения; конструктор и публичные методы `TelemetryIngest` не меняются.
- Потоки остаются daemon-потоками; потребители не должны занимать процессор активным ожиданием.

## Как будет проверено
Видимые тесты отправляют показания сразу после создания сервиса. Скрытые тесты делают паузы между всплесками, используют четыре потребителя и два производителя и проверяют, что все показания обработаны ровно один раз, а закрытие укладывается в отведённое время.
