# Диспетчеризация перетоков мощности

Диспетчерская система распределительной сети перераспределяет нагрузку между узлами (подстанциями). Сервис `FlowDispatcher` выполняет:
- `shift(from, to, megawatts)` — одиночный переток нагрузки с одного узла на другой;
- `applyBatch(flows)` — пакет перетоков, рассчитанный планировщиком. Пакет применяется **целиком или не применяется вовсе**: если хотя бы один переток нарушает ограничения узла, сеть остаётся в исходном состоянии.

Одиночные перетоки поступают от операторов, пакеты — от планировщика; всё выполняется параллельно. Состояние каждого узла защищено его монитором.

## Что наблюдается
После внедрения планировщика система диспетчеризации начала зависать в часы пиковой нагрузки. Каждое зависание — взаимная блокировка между потоками, применяющими пакеты, и потоками одиночных перетоков. Порядок перетоков внутри пакета определяется планировщиком и может быть любым; один узел может встречаться в пакете несколько раз.

## Что нужно сделать
Устраните взаимные блокировки в `FlowDispatcher`. Одиночные перетоки и пакеты должны оставаться атомарными, суммарная нагрузка сети — неизменной, ограничения мощности узлов — соблюдаться в любой момент.

## Ограничения
- Публичные методы и их сигнатуры менять нельзя.
- Классы `GridNode` и `Flow` доступны только для чтения.
- Проверки перетоков и пакетов должны работать как раньше.

## Как будет проверено
Видимые тесты проверяют операции в одном потоке. Скрытые тесты применяют пакеты с разным порядком перетоков и одиночные перетоки одновременно из нескольких потоков с ограничением времени.
