# Зависание перемещений между складами

Логистическая компания держит товар на трёх региональных складах. Сервис `StockMovementService` выполняет две операции:
- `move(from, to, sku, quantity)` — перемещение партии товара между складами по заявке;
- `rebalance(a, b, sku)` — выравнивание остатков товара между двумя складами (излишек переезжает туда, где товара меньше).

Заявки обрабатывает пул потоков. Правило системы: остатки склада меняются только под монитором объекта `Warehouse`.

## Что наблюдается
Во время ночного выравнивания остатков, которое идёт параллельно с дневными заявками, обработка периодически «замирает»: заявки не выполняются, потоки пула висят. Разработчики воспроизвели зависание на встречных перемещениях между двумя складами и на «круговых» перемещениях между тремя складами (А → Б, Б → В, В → А).

## Что нужно сделать
Устраните зависания в `StockMovementService` так, чтобы перемещения и выравнивание оставались атомарными и общее количество товара на складах не менялось.

## Ограничения
- Публичные методы и их сигнатуры менять нельзя.
- Класс `Warehouse` доступен только для чтения; правило блокировок сохраняется.
- Логика выравнивания остатков и проверки аргументов должны работать как раньше.

## Как будет проверено
Видимые тесты проверяют операции в одном потоке. Скрытые тесты выполняют встречные, круговые и смешанные операции из нескольких потоков с ограничением времени.
