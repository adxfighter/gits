# REST API v1.0

Все пути — относительно `/api` (через nginx: `http://localhost:8080/api/...`). Ошибки возвращаются в формате Problem Details (RFC 9457). Запросы, меняющие данные, требуют CSRF-токена: `GET /api/auth/csrf` ставит cookie `XSRF-TOKEN`, его значение передаётся в заголовке `X-XSRF-TOKEN`.

## Работодатель
Сессия — cookie после входа.

| Метод и путь | Назначение |
|---|---|
| `GET /auth/csrf` | выдать CSRF-токен |
| `POST /auth/login` | вход по email и паролю (ограничение частоты по IP) |
| `GET /auth/me` | текущий пользователь; без сессии — 401 |
| `POST /auth/logout` | выход: сессия завершается, ответ 204 |
| `POST /invites` | создать приглашение кандидата (`candidateLabel`, `targetLevel`); ответ содержит ссылку |
| `GET /invites` | приглашения своей компании (кратко, без результатов) |
| `GET /employer/invites?status=` | приглашения с результатами: сессия, её статус и даты, предварительный балл, уровень доверия (худший по заданиям без калибровочного блока); `status` — фильтр по статусу приглашения. Неиспользованное приглашение с истёкшим сроком показывается как EXPIRED |
| `DELETE /employer/invites/{id}` | отозвать неиспользованное приглашение (CREATED); повтор — 204, использованное — 409; вход по ссылке и отзыв не выполняются одновременно (блокировка строки приглашения) |
| `GET /employer/sessions/{sessionId}/report` | отчёт по сессии (см. ниже) |
| `GET /employer/session-tasks/{id}/replay?fromSeq=&limit=` | данные для воспроизведения задания (см. ниже) |

Работодатель видит только данные своей компании: чужие приглашения, сессии и задания — 404. `/invites` и `/employer/**` — только роль EMPLOYER (администратору — 403); `/auth/me` и `/auth/logout` — любой вошедший пользователь. `POST /auth/login`: неверные email или пароль — 401 «Неверный email или пароль», превышение частоты попыток — 429.

### Отчёт по сессии
Общий предварительный балл и время его расчёта, уровень доверия, по каждому заданию (включая калибровочный блок, `kind: CALIBRATION`): шаблон (`templateCode`, `templateTitle`), компетенции (коды `competencies` и их русские названия `competencyTitles` в том же порядке — из `tasks/competencies.yaml` банка задач; без банка вместо названия код), уровень варианта, итог последнего SUBMIT (`submitStatus`, `submitCompiled`), пройдено скрытых тестов `hiddenTestsPassed` из `hiddenTestsTotal` (если скрытые тесты не запускались — не скомпилировалось, превышено время, ошибка запуска — `hiddenTestsPassed` = 0, `hiddenTestsTotal` = `null`), время от открытия до отправки (`durationSeconds`), число запусков RUN, индикаторы достоверности с пояснениями и `trustLevel`, финальный код — редактируемые файлы, отправленные на проверку (без SUBMIT — последний сохранённый снимок). Балл (`preliminaryScore`, `scorePerTask`), индикаторы и уровень доверия считаются после завершения сессии, когда проверены все её решения ([indicators.md](indicators.md)); до расчёта они `null`. Индикаторы — объект `{имя: {value, explanation}}`, пояснения на русском. Уровень доверия сессии — худший по заданиям; индикаторы калибровочного блока в него не входят. Файлы SOLUTION и HIDDEN_TEST в отчёт не попадают.

### Воспроизведение
`sessionId` — сессия задания (путь назад к отчёту); `initialFiles` — файлы, которые видел кандидат (STARTER, READONLY, VISIBLE_TEST); `runs` — все запуски с временными метками, `offsetMs` (время создания запуска в миллисекундах от открытия задания на сервере — примерное место на шкале `t`) и результатом (без вывода и имён тестов); `events` — события `edit`, `paste`, `cursor`, `select`, `focus`, `blur`, `visibility`, `run`, `submit`, `completion` по порядку (нажатия клавиш и изменение размера не передаются), с полями из [telemetry.md](telemetry.md) и номером пакета `seq`. Пагинация по пакетам: `limit` — число пакетов (по умолчанию 50, от 1 до 200; в пакете до 2 000 событий), следующая страница начинается с `nextSeq`; на последней странице `nextSeq` = `null`. Отрицательный `fromSeq` — 400. `initialFiles` и `runs` приходят на каждой странице.

## Администратор
Роль ADMIN (у администратора нет компании); работодателю — 403, без входа — 401.

| Метод и путь | Назначение |
|---|---|
| `GET /admin/tasks` | банк задач: шаблоны (`code`, `title`, `baseLevel`, `competencies`) и их варианты — `id`, `code`, `kind`, `level`, `status` (`VALIDATED`, `DISABLED`), `domain`, итог валидации (`validationPassed`, `failedChecks` — id непройденных проверок, `referenceMaxMs` — самый долгий прогон решения), `issued` — сколько раз вариант выдан кандидатам |
| `GET /admin/tasks/variants/{id}` | вариант (`code`, `templateCode`, `templateTitle`, `kind`, `level`, `status`, `timeLimitMin`): условие (`statementMd`), отчёт валидации (`validationReport`), число выдач и **все** файлы, включая SOLUTION и HIDDEN_TEST — только здесь и только администратору; неизвестный вариант — 404 |
| `GET /admin/sessions` | сессии всех компаний, новые первыми: `sessionId`, `companyName`, `candidateLabel`, `targetLevel`, `status`, `startedAt`, `finishedAt`, `preliminaryScore`, `scoreComputedAt`, `trustLevel` (без разминки) |
| `GET /admin/sessions/{id}/demo-export?label=` | завершённая сессия как демо-файл `gits-demo-session/1` (для `gits-taskbank demo-seed`, [ADR 0014](adr/0014-e2e-and-demo-data.md)) под меткой `label` (1–200 символов): время, задания по коду варианта с кодом, запусками и телеметрией; без токена, IP, user agent и метки кандидата. Идущая сессия — 409, нет метки — 400 |
| `POST /admin/sessions/{id}/scoring` | пересчитать индикаторы и балл завершённой сессии; для идущей или с непроверенными решениями — 409 |
| `GET /admin/export?from=&to=` | выгрузка для исследования: ZIP (`application/zip`, скачивание файлом) с сессиями, начатыми в период. `from`, `to` — дни `YYYY-MM-DD` по UTC включительно, оба необязательны, годы 2000–9998; `from` позже `to` или дата не по формату — 400. Имя файла — `gits-export[-from][-to].zip`. Внутри — `README.md` с описанием полей, `sessions.jsonl`, `tasks.jsonl`, `runs.jsonl`, `telemetry.jsonl`, `indicators.jsonl`, `manifest.json` (период и число строк). Псевдонимизация: вместо сессий, заданий и компаний — случайные идентификаторы этого архива (`s-…`, `t-…`, `c-…`); меток кандидатов, email, названий компаний, IP (и их хешей), user agent нет. Каждая выгрузка записывается в `audit_log` (`RESEARCH_EXPORT`). Описание полей — [README архива](../backend/gits-api/src/main/resources/export/README.md) |

## Кандидат
Доступ — подписанная cookie, которую выдаёт `POST /candidate/enter`. Все пути, кроме `enter`, `me` и `consent`, доступны только после согласия на обработку данных; кандидат видит только свою сессию (чужие задания и запуски — 404). После завершения сессии приглашение переходит в COMPLETED и cookie больше не действует (401).

| Метод и путь | Назначение |
|---|---|
| `POST /candidate/enter` | вход по токену из ссылки |
| `GET /candidate/me` | приглашение и признак согласия |
| `GET /candidate/consent`, `POST /candidate/consent` | текст согласия и его принятие |
| `POST /candidate/session/start` | начать сессию: калибровочный блок и 3 задачи из разных шаблонов под уровень приглашения; повторный вызов возвращает ту же сессию |
| `GET /candidate/session` | состояние: задания (порядок, статус, лимиты), `deadline` и `remainingSeconds` по серверным часам |
| `GET /candidate/tasks/{id}` | условие, файлы STARTER/READONLY/VISIBLE_TEST и текущий снимок кода; первое открытие начинает задание; `beaconToken` — одноразовый токен для sendBeacon; `telemetryNextSeq` и `telemetryLastT` — где продолжается телеметрия задания после перезагрузки страницы |
| `PUT /candidate/tasks/{id}/code` | автосохранение `{"files": {путь: содержимое}}` — только редактируемые файлы |
| `POST /candidate/tasks/{id}/run` | запуск на видимых тестах (тело `{"files": …}` необязательно — иначе берётся сохранённый снимок); ответ 202 с `runId` |
| `POST /candidate/tasks/{id}/submit` | отправка на проверку скрытыми тестами; после неё задание закрыто для правок |
| `GET /candidate/runs/{runId}` | статус и результат запуска |
| `POST /candidate/tasks/{id}/retyping` | разминка, часть 1: сравнение перепечатки (`Typing.txt`) с образцом (`Sample.txt`) без пробельных символов и поиск вставок в телеметрии; код не компилируется и не запускается. Тело `{"files": …}` необязательно (сохраняется как снимок). Ответ: `similarityPercent`, `passed` (≥ 95% и без вставки), `pasteSuspected` (вставка 10+ непробельных символов), `message` для кандидата. Не разминка — 400, задание закрыто — 409 |
| `POST /candidate/tasks/{id}/telemetry` | пакет телеметрии ввода (JSON или text/plain от sendBeacon), см. [telemetry.md](telemetry.md); чужое задание здесь — 403 (по P08), в остальных путях — 404 |
| `POST /candidate/session/finish` | завершить сессию |

### Правила сессии
Параметры — `gits.session.*` в `application.yml`.

| Правило | Значение | Ответ при нарушении |
|---|---|---|
| Длительность сессии | 90 минут с момента старта | изменения после срока — 409 |
| Автосохранение | не чаще 1 раза в 5 секунд; RUN/SUBMIT с телом `files` тоже сохраняет снимок и считается сохранением | 429 |
| Размер снимка кода | не более 256 КБ (все редактируемые файлы вместе) | 413 |
| Изменение readonly-файла или неизвестного пути | запрещено | 400 |
| Активные запуски | не более 1 на кандидата (RUN или SUBMIT) | 409 |
| Запуски RUN | не более 60 на задачу (SUBMIT не считается) | 429 |
| Повторная отправка | задание после SUBMIT закрыто | 409 |

Каждые 30 секунд планировщик находит сессии с истёкшим временем: незавершённые задания отправляются на проверку с последним сохранённым снимком, сессия получает статус EXPIRED, приглашение — COMPLETED. `session/finish` делает то же со статусом FINISHED (после истечения срока — EXPIRED). Запросы одного кандидата и планировщик выполняются последовательно (блокировка строки приглашения), поэтому двойной клик или вторая вкладка не создают второй сессии, второго активного запуска или повторного SUBMIT. После завершения сессии считаются индикаторы и предварительный балл — как только runner проверит её решения ([indicators.md](indicators.md)).

### Что кандидат не получает никогда
- Файлы SOLUTION и HIDDEN_TEST, отчёт валидатора (`validation_report`) и контрольную сумму варианта — ни в одном ответе. Это проверяют тесты безопасности API.
- Для SUBMIT: имена, сообщения и вывод скрытых тестов. `GET /candidate/runs/{id}` возвращает статус запуска, `compiled`, `testsTotal`, `testsPassed` и длительность; список тестов пуст, вывод компилятора и stdout не передаются.

### Подбор заданий
Состав зависит от уровня приглашения:
- JUNIOR — junior, junior, middle;
- MIDDLE — junior, middle, senior или middle ×3;
- SENIOR — middle, senior, senior.

Шаблоны задач различаются. Калибровочный блок выбирается независимо от уровня. Варианты, выданные трём последним кандидатам компании, не используются, пока банк это позволяет. Выбор детерминирован по `random_seed` сессии (`TaskSelectionService`). Источник вариантов — `TaskProvider` (в v1.0 — банк задач, `StaticPoolTaskProvider`); интерфейс `LlmClient` — задел для генерации вариантов в следующих версиях.
