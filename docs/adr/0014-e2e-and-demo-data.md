# ADR 0014. E2E-тесты и демо-данные

**Статус:** принято. **Дата:** 2026-09-28. **Этап:** P16.

## Контекст
Нужны сквозные тесты против собранного стека (P16) и демо-сессии, которые показывают отчёт и воспроизведение сразу после установки, без прохождения оценки вручную.

## Решения
| Вопрос | Решение | Обоснование |
|---|---|---|
| Инструмент E2E | Playwright (`e2e/`, Chromium), против `docker compose` на `http://localhost:8080` (`GITS_URL`). Один воркер, сценарии последовательны и опираются друг на друга | Реальные браузер, nginx, api, runner и песочница; runner один на всех |
| Сценарии | Работодатель создаёт приглашение; кандидат проходит разминку и 3 задачи; работодатель открывает отчёт (балл 100) и воспроизведение (код совпадает с итоговым); повторный вход по использованной ссылке; истечение времени | Пять сценариев P16 |
| Решения задач | Тестовый хелпер находит вариант по заготовке (путь и содержимое редактируемых файлов совпадают с `starter/`) и берёт `solution/` из `tasks/`; код вставляется в модели Monaco через его API, а не посимвольно | Интерфейс кандидата решений не видит; посимвольный ввод сделал бы тест долгим |
| Истечение времени | Сессию сдвигают назад на 91 минуту SQL-запросом через `docker compose exec postgres psql` — единственный «чёрный ход» тестов | Ждать 90 минут нельзя; отдельная конфигурация стека усложнила бы CI |
| CI | Задача `e2e`: стек из `.env.example`, образ песочницы, `docker compose up --build --wait`, Playwright; при сбое — отчёт Playwright и логи контейнеров. Повторов нет: сценарии зависят друг от друга | Проверяется то же, что увидит владелец |
| Формат демо-сессии | JSON `gits-demo-session/1` (`DemoSession` в gits-taskbank): метка, уровень, время, задания по коду варианта с кодом, запусками с результатами и пакетами телеметрии. Без токена, IP, user agent и метки настоящего кандидата | Банк задач уже в базе; файл ссылается на варианты по коду |
| Экспорт | `GET /api/admin/sessions/{id}/demo-export?label=` (ADMIN) — завершённая сессия под новой меткой | Демо-сессии делаются из настоящих записей через платформу |
| Импорт | `gits-taskbank demo-seed <каталог> [--employer]` — в компанию работодателя `DEMO_EMPLOYER_EMAIL`; время сдвигается так, что сессия закончилась за час до импорта; сессия с уже существующей меткой пропускается (повторный запуск безопасен); неизвестный вариант — сессия пропускается с сообщением. Балл и индикаторы считает gits-api, как для любой завершённой сессии | Демо выглядит свежим; один расчёт балла на всю платформу |
| Запуск без JDK | Образ `gits-taskbank:local` (цель `taskbank` backend/Dockerfile) и сервис compose `taskbank` в профиле `tools`: `docker compose --profile tools run --rm taskbank demo-seed /seed/demo-sessions` | Для демо достаточно Docker |
| Сброс демо | `scripts/demo-reset.(ps1\|sh)`: подтверждение (`-Yes`/`--yes`), `docker compose down -v`, `scripts/up.*`, ожидание здоровья, `demo-seed` | Одна команда перед показом |
| Запись демо-сессий | `npm run record-demo` (`e2e/record`): сценарий проходит оценку через настоящий интерфейс кандидата три раза — честное решение (своя скорость, правки только нужного места, опечатки, запуск тестов), решение крупными вставками (вставка всего решения из буфера), перепечатывание со второго экрана (уход со страницы, пауза 40 с, быстрый набор всего решения сверху вниз без правок) — и выгружает их в `seed/demo-sessions` | Телеметрия — та, что собирает платформа, а не сочинённая; записи можно заменить настоящими сессиями команды через тот же экспорт |

## Последствия
- Демо-сессии записаны сценарием, а не человеком: поведение правдоподобное, но упрощённое (равномерные опечатки, синтетический уход со страницы). Для показа заказчику их стоит заменить записями команды — экспорт для этого есть.
- Если в банке задач поменяется вариант, использованный в демо-файле, воспроизведение этой демо-сессии разойдётся с итоговым кодом (ADR 0012); файлы стоит перезаписать.
- E2E меняют данные стенда (приглашения и сессии с меткой `E2E …`); для чистого показа — `demo-reset`.
