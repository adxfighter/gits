# Индикаторы достоверности и предварительный балл

> **Экспериментальные правила v1.0; в версии НИОКР заменяются моделями машинного обучения.** Индикаторы и уровень доверия — подсказка работодателю, где стоит посмотреть воспроизведение сессии. Выводы о кандидате делает человек, а не автомат.

Расчёт выполняет `ScoringService` (gits-api, пакет `scoring`). Вход — телеметрия задания ([telemetry.md](telemetry.md)), запуски и результат последнего SUBMIT. Индикаторы задания сохраняются в `session_indicators`, балл сессии — в `session_score`. Оба видны в отчёте работодателя: `GET /api/employer/sessions/{id}/report`, см. [api.md](api.md).

## Когда считается
- **После завершения сессии** (`session/finish` или истечение времени). Незавершённые задания в этот момент только отправлены на проверку, их SUBMIT ещё в очереди runner. Поэтому сессию считает планировщик: раз в `gits.scoring.check-interval` (15 с) он берёт завершённые сессии без балла, у которых нет SUBMIT в очереди или в работе. Сразу после завершения делается попытка расчёта — на случай, если все решения уже проверены.
- **Потерянная проверка.** SUBMIT, который ждёт дольше `gits.scoring.stuck-submit-after` (15 мин, например, runner не работал), и SUBMIT, завершившийся ошибкой runner (`ERROR`), — сбой платформы, а не результат кандидата. Сессия считается без этой задачи, в `scorePerTask` у неё есть поле `excluded` с пояснением. Превышение времени (`TIMEOUT`) и ошибка компиляции — результат кода: 0 пройденных.
- **Ошибки расчёта.** Если сессию не удалось посчитать (например, повреждённые данные), планировщик повторяет попытку со всё большей паузой (до часа) и не задерживает остальные сессии.
- **Повторно по запросу администратора:** `POST /api/admin/sessions/{id}/scoring` (роль ADMIN). Пересчёт заменяет прежние строки и записывается в `audit_log`. Для идущей сессии или сессии с непроверенными запусками — 409.

Один расчёт сессии не пересекается с другим: берётся блокировка строки приглашения.

## Индикаторы задания
Пороги — `gits.indicators.*` в `application.yml`. События берутся в порядке `t`.

| Индикатор | Как считается |
|---|---|
| `pasteRatio` | символы, вставленные вставкой (`edit` с `source: paste`), делённые на объём итогового редактируемого кода. Итоговый код — отправленный на проверку, без SUBMIT — последний сохранённый снимок. Не больше 1. Не считаются вставка, сразу отменённая Ctrl+Z, и вставка своего кода, скопированного или вырезанного в редакторе (перенос кода): её длина совпадает с длиной предшествующего `copy` |
| `largestPaste` | наибольшая вставка, символов (по тем же правилам) |
| `focusLoss` | `count` — сколько раз кандидат уходил со страницы; `seconds` — суммарная длительность. Уход — `blur` окна или скрытая вкладка (`visibility: hidden`), одновременные уходы считаются одним эпизодом. Возврат — `focus` и видимая вкладка, либо любой ввод. Любая активность на странице (ввод, курсор, выделение, запуск) тоже завершает эпизод — например, после перезагрузки страницы, которая не сообщила о фокусе заново. Эпизод, не закрытый до конца телеметрии, длится до последнего события |
| `burstMax` | наибольшая скорость набора, символов в секунду, в скользящем окне `burst-window` (5 с). Считаются нажатия клавиш, которые печатают символ (`kd` классов letter, digit, space, punct, bracket, enter, tab). Поэтому вставки, автодополнение и то, что редактор добавляет сам (отступы, закрывающие скобки), скорость не завышают, и она сравнима со скоростью на разминке |
| `burstRelative` | `burstMax`, делённый на базовую скорость кандидата — `burstMax` калибровочного блока. Нет базовой скорости — нет значения |
| `idleThenBurst` | число эпизодов: пауза без ввода дольше `idle-pause` (30 с), затем больше `idle-burst-chars` (150) символов за `idle-burst-window` (20 с) без вставки. Время до первого ввода (чтение условия) и время, пока страница была закрыта (его нет на шкале `t`), паузой не считаются |
| `linearity` | доля правок, сделанных на «фронте набора» своего файла (набор сверху вниз без возвратов), от всех правок. Правка на фронте — вставка без замены не левее конца ранее набранного текста (допуск `linear-tolerance`, 2 символа). Правки выше фронта сдвигают его |
| `editRatio` | удалённые символы (`rangeLength` всех правок), делённые на вставленные (`textLength`) |
| `timeToFirstRun` | секунды от открытия задания до первого RUN; `null`, если тесты не запускались |
| `runsCount` | число RUN |

Служебные значения для правил: `typedChars` — набрано вручную символов, `pastedChars`, `telemetryEvents` — событий телеметрии задания.

В отчёте каждый индикатор хранится как `{"value": …, "explanation": "…"}` с пояснением на русском. Например: `"pasteRatio": {"value": 0.62, "explanation": "Доля итогового кода, пришедшая вставкой: 62% (410 симв. вставлено)."}`. Сработавшие правила — в `trustReasons.value`.

## Уровень доверия (trust_level)
Правила — `gits.indicators.rules` в `application.yml`: уровень, условия и пояснение. Условия записываются как `"имя оператор число"`, операторы `>`, `>=`, `<`, `<=`, `==`, и должны выполняться все. Уровень задания — худший среди сработавших правил, GREEN, если не сработало ни одно. Условие с неизвестным значением (например, `burstRelative` без разминки) не срабатывает. Ошибка в записи правила — неверный оператор, число или имя индикатора — останавливает запуск api.

Правила v1.0:

| Уровень | Условия | Пояснение |
|---|---|---|
| RED | `pasteRatio > 0.5` | больше половины итогового кода добавлено вставкой |
| RED | `idleThenBurst >= 2`, `focusLossSeconds > 60` | несколько всплесков после пауз при долгом уходе со вкладки |
| YELLOW | `pasteRatio > 0.25` | заметная доля кода — вставкой |
| YELLOW | `largestPaste > 300` | крупная вставка |
| YELLOW | `idleThenBurst >= 1` | всплеск после паузы |
| YELLOW | `focusLossSeconds > 120` | вкладку надолго покидали |
| YELLOW | `burstRelative > 2.5` | пиковая скорость намного выше скорости на разминке |
| YELLOW | `linearity > 0.9`, `typedChars > 300` | почти строго сверху вниз — похоже на перепечатку |
| YELLOW | `telemetryEvents == 0` | нет телеметрии — оценить нельзя |

Уровень доверия сессии (в списке приглашений и в отчёте) — худший по заданиям.

**Калибровочный блок (разминка).** Индикаторы разминки считаются и показываются, но в уровень доверия сессии не входят. Её `burstMax` — базовая скорость набора кандидата, от которой считается `burstRelative` остальных заданий. В разминке нет автодополнения и автозакрытия скобок (P10), поэтому её скорость — скорость обычного набора.

## Предварительный балл
> **Предварительный, до психометрической калибровки.** Эта пометка сохраняется вместе с баллом (`scorePerTask.note`).

- Балл задания — доля пройденных скрытых тестов последнего SUBMIT. Если проверка не дошла до тестов (не скомпилировалось, превышено время, ошибка запуска), пройдено 0.
- Вес — уровень варианта задачи (`gits.scoring.weights`): junior 1, middle 1,5, senior 2.
- `preliminary_score` = 100 × Σ(вес × доля) / Σ(вес), от 0 до 100, два знака после запятой. Калибровочный блок в балл не входит.
- `scorePerTask.tasks` — по каждому заданию: уровень, вес, пройдено и всего скрытых тестов (`null`, если тесты не запускались), доля; у задачи, не проверенной из-за сбоя платформы, вместо них — `excluded` с пояснением, и в балл она не входит.
