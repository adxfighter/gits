# Сканирования перепечатанных посылок теряются

Сортировочные центры отправляют события сканирования посылок в журнал `ScanJournal`. Журнал группирует сканирования по ссылке на посылку `ParcelRef`. Посылку определяют три поля: перевозчик, трек-номер и хаб отправки. Кроме того, в ссылке хранится версия этикетки: если этикетка повреждена, её перепечатывают, и версия увеличивается. По правилам компании перепечатанная этикетка относится к **той же** посылке, поэтому версия этикетки в `equals` не участвует.

## Что наблюдается
После перепечатки этикетки история посылки распадается на части. Сканирования до и после перепечатки не видны вместе, а число посылок в журнале растёт, хотя новых посылок не было.

## Что нужно сделать
Исправьте `ParcelRef`, чтобы все сканирования одной посылки собирались вместе независимо от версии этикетки.

## Ограничения
- `ScanJournal` доступен только для чтения.
- Конструктор `ParcelRef(String carrier, String trackingNo, String originHub, int labelVersion)` и методы доступа должны остаться прежними. Версия этикетки по-прежнему доступна через `labelVersion()`.
- Смысл равенства из условия менять нельзя.

## Как будет проверено
Видимые тесты сканируют посылки без перепечатки. Скрытые тесты перепечатывают этикетки и проверяют контракт `equals`/`hashCode`.
